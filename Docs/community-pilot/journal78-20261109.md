## Funktion
Tagebuch im SoulNexus lädt erst nach ausdrücklichem Öffnen. Eigene Erinnerungen:Sanctuary-Besuch, Begegnung oder Gedanke/nächster Schritt. Alle dauerhaft vorgesehenen Notizen sind ausdrücklich selbst eingetragen, kein Beleg für tatsächliche Teilnahme, physische Nähe, Berechtigungen oder Belohnungen.
Titel80/Notiz1000Zeichen; freiwilliger Zeitpunkt, leer bleibt unbekannt. Erfassungszeit wird nicht als Erlebnisdatum ausgegeben. Ändern/Abbrechen und zweistufige Löschbestätigung. Neuöffnen verwirft Entwurf; Kontowechsel verwirft späte Antworten und Formularinhalt. Kein globaler localStorage und keine Kontakt-/Standortaufzeichnung. Bestehende Fortschritts-/Symbolanzeige bleibt getrennt.
Aktuell höchstens100neueste Einträge lesbar, begrenzte Liste ehrlich beschriftet; ältere bleiben gespeichert, weitere Navigation noch offen.

## Speicher-/Sicherheitsgrenze
Route private-journal in bestehender registrations-Funktion; keine neue Hostingfunktion. membership-auth prüft tatsächlichen Bearer und vorhandene Kontosperren. Eigener Datenbankclient benutzt ausschließlich vorhandenen öffentlichen Projektschlüssel plus verifizierten Bearer; KEIN service_role-Fallback für Tagebuchzugriffe.
SQL-Entwurf sql/pass78-private-journal.sql:neue private ownergebundene Tabelle, RLS für SELECT/INSERT/UPDATE/DELETE, anonyme Sitzungen ausgeschlossen. Begrenzte Spaltengrants verhindern Änderung von Eigentümer/Erfassungszeit und generierter Quelle. source ist zwingend self_reported. API übernimmt Owner ausschließlich aus bestätigter Sitzung, keine clientseitigen Rollen/EXP/Evidenzfelder. Wiederholung einer identischen Erstanlage mit derselben UUID erzeugt keinen Doppeleintrag; abweichender Inhalt liefert Konflikt statt stillen Überschreibens. Keine zusätzliche XP/FLOW/Rolle.
SQL ist ein Review-/Setupkandidat, KEINE bereits angewandte Migration. Supabase CLI ist im geprüften Kommandozugriff nicht vorhanden; keine Version/Installation erfunden, keine benannte Migration von Hand erzeugt. Vor Release über vorhandenen Migrationsablauf übernehmen; Zielumgebung/Advisors/echte Auth und Anbieterkonfiguration getrennt prüfen.
Keine Host-Zugangsdaten gelesen, keine neuen Konten oder kostenpflichtigen Aufrufe.
